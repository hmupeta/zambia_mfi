Nimbus Microfinance Platform

A comprehensive, enterprise-grade digital infrastructure designed for Microfinance Institutions (MFIs) operating in Zambia.

Version 1.0 • Last Updated: October 2026

1. Executive Overview

Nimbus is a multi-tenant, cloud-native core banking and loan management system tailored for the Zambian microfinance sector. It addresses the critical challenge of financial inclusion by providing a paperless, mobile-first ecosystem for loan origination, credit scoring, and mobile money collections.

The platform is designed to operate efficiently in low-connectivity environments (via the Field App) while providing HQ Administrators with real-time, Bank of Zambia (BoZ) compliant financial reporting and audit capabilities.

2. System Architecture

The Nimbus ecosystem is composed of four primary, fully integrated components:

  • The Web Portal (Django + HTMX): The central command center. It is secured by Role-Based Access Control (RBAC) and is used by internal staff to manage operations, review applications, and generate reports.
  • The Field App (Flutter): An offline-first mobile application for Loan Officers. It uses local database storage (Hive) to capture KYC documents (NRC photos) and loan applications in the field, syncing with the server when a connection is available.
  • The Customer App (Flutter): A self-service mobile app for borrowers. Features include biometric login, loan application submission, and push USSD prompts for mobile money repayments.
  • The Customer Web Portal: A responsive web interface offering the same self-service capabilities as the mobile app for desktop users.

3. User Journeys & Roles

The platform enforces strict Segregation of Duties (Four-Eyes Principle) at the database level to prevent internal fraud.

3.1 The HQ Administrator (The Architect)

Configures the structural rules of the MFI.

  1. Hierarchy Setup: Creates branches (e.g., "Ndola Branch") and provisions user accounts with specific roles (Manager, Officer, Teller).
  2. Product Configuration: Defines loan products (e.g., "SME Loan" with a 25% flat interest rate, 12-month max tenure, and specific GL mapping).
  3. Workflow Configuration: Establishes multi-stage approval pipelines (e.g., Officer -> Manager -> HQ Admin sign-off for loans > K50,000).
  4. System Settings: Configures SMS/WhatsApp notification templates, global grace periods, and mobile money API credentials.

3.2 The Loan Officer (The Field Agent)

Responsible for client acquisition and initial credit assessment.

  1. Client Onboarding: Uses the Field App to capture the client's full name, NRC number, and phone number. Takes high-resolution photos of the client's face and their physical NRC document.
  2. Appraisal: Inputs the client's monthly income, expenses, existing debts, and net worth to calculate the Debt-to-Income (DTI) ratio.
  3. Submission: Submits the application, which is queued for the Branch Manager.

3.3 The Branch Manager (The Approver)

Responsible for credit risk and disbursement authorization.

  1. Credit Review: Reviews the uploaded KYC documents and the officer's appraisal. Checks the auto-generated credit score (Grade A-D).
  2. Approval: Approves the loan. The system instantly generates the Loan record and the repayment schedule (installments).
  3. Disbursement: Initiates the payout. Selects "MTN MoMo" or "Airtel Money". The system triggers a real-time API call to transfer funds from the MFI wallet to the customer's wallet, and automatically posts the required Journal Entries.

3.4 The Customer (The Borrower)

Self-service access to credit and repayment.

  1. Repayment: Logs into the Customer App, navigates to the active loan, and selects "Make a Payment".
  2. USSD Authorization: The app sends a Request-to-Pay to the backend, which triggers a USSD prompt (e.g., *150#) on the customer's phone. They enter their PIN to authorize the deduction.
  3. Instant Update: The app polls the backend and instantly reflects the new loan balance and updated repayment history.

4. The Loan Lifecycle

Every loan transitions through a strict state machine:

DRAFT → SUBMITTED → UNDER REVIEW → APPROVED → DISBURSED
  • Credit Scoring: The system runs a proprietary algorithm evaluating Debt-to-Income, Net Worth coverage, and Repayment History to assign a Grade (A, B, C, or D).
  • Amortization: Supports Flat Interest and Reducing Balance methods. Installments are generated dynamically based on the client's chosen frequency (Daily, Weekly, Bi-Weekly, Monthly).
  • Delinquency (DPD): If a payment is missed, the loan enters a "Days Past Due" state, escalating penalty interest and changing the loan classification (Watch, Substandard, Doubtful, Loss).

5. Accounting Subsystem

Nimbus uses a full Double-Entry Accounting engine. Every financial event triggers an automated Journal Entry (JE). There is no manual data entry required for standard operations.

6. Mobile Money Integration

The platform is deeply integrated with MTN MoMo and Airtel Money APIs, supporting two distinct transaction types per branch:

  • Collections (Inbound): Uses the "Request to Pay" API. When a repayment is due, the system sends a request to the customer's wallet, prompting them for their PIN.
  • Disbursements (Outbound): Uses the "Transfer" API. When a manager approves a loan, the funds are instantly pushed to the customer's wallet without the customer needing to do anything.
  • Environment Management: The system supports both Sandbox and Production environments, storing encrypted API keys, Client IDs, and Subscription Keys securely per branch.

7. Reporting Matrix

Reports are categorized by stakeholder and regulatory requirement.

Financial Statements

  • Trial Balance: Ensures all debits equal credits.
  • Income Statement: Tracks profitability (Interest - Expenses).
  • Balance Sheet: Snapshot of Assets, Liabilities, and Equity.

Bank of Zambia (BoZ) Returns

  • Portfolio at Risk (PAR): Measures overdue loans (PAR 30, PAR 90).
  • Non-Performing Loans (NPL): Loans 90+ days overdue.
  • Loan Loss Provision: Reserves held for bad debt.

Operational Reports

  • Daily Collections: Cash and MoMo received per branch.
  • Aging Report: Buckets loans by delinquency (1-30, 31-60 days).
  • Disbursement Log: Record of all outgoing funds.

Audit & Security

  • Audit Trail: Immutable log of all system actions.
  • Bank Reconciliation: Matches system ledger to bank statements.
  • MoMo Float Report: Tracks real-time wallet balances.

8. Security & Compliance

  • Data Isolation (Multi-Tenancy): The database is logically partitioned. A Branch Manager in Lusaka cannot access client data or loans belonging to the Ndola Branch.
  • Credential Encryption: All third-party API credentials (MTN Subscription Keys, API Secrets) are encrypted at rest using Fernet symmetric encryption. They are never exposed in plain text in the database.
  • Segregation of Duties: Hard-coded business rules prevent the same user from creating a loan, approving it, and disbursing it. System administrators cannot bypass this.
  • CSRF & XSS Protection: All web forms and API endpoints are protected against Cross-Site Request Forgery (CSRF) and Cross-Site Scripting (XSS).

9. Glossary of Terms

KYC (Know Your Customer)
The mandatory process of identifying and verifying a client's identity (via NRC and photograph) before providing financial services.
NRC (National Registration Card)
The primary identity document for Zambian citizens, required for all loan applications.
DPD (Days Past Due)
The number of days a loan installment is overdue. Used to classify loans and calculate penalties.
PAR (Portfolio at Risk)
A percentage representing the portion of the loan portfolio that is overdue. PAR 30 is the industry standard for measuring risk.
MoMo (Mobile Money)
Digital wallet services provided by telecom operators (MTN, Airtel) used for disbursing loans and collecting repayments.
GL (General Ledger)
The master record of all financial transactions, ensuring the accounting equation (Assets = Liabilities + Equity) remains balanced.
